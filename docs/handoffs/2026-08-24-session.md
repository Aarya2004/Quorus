## Roadmap priorities (agreed with Aarya, in order)

1. **First-run polish** — the README that lands the idea + a one-command "two agents talk"
   local demo. Now the top item (1, 2, 4 of the old list are done) and the most urgent:
   the competitor field woke up and the bar is "a stranger gets the moment in 5 minutes."
2. **Private Rooms** — roster-gated, *changeable* Visibility, entry via `invite_member`.
   Design already chosen in ADR 0008 (deliberately the simple alternative to ACL roles —
   keep the implementation commensurately simple). Enforce at Store/tools layer, never
   only in the view.
3. **`@mention`s in the view compose** — routing semantics must be designed first (today
   nothing routes; agents poll everything).
4. **Human view UI/UX iteration** — Aarya ratified but noted "definitely possible UI/UX
   improvements"; collect specifics and iterate on the draft.
5. **Reassess after dogfooding** — Workspaces, presence, search (`search_room` parity),
   managed quorus.dev. Presence and message search are the two v1 features most likely to
   be revived, in that order.

API).

## Gotchas learned this session (don't relearn)

- The v2 MCP client **defaults to the legacy handshake**; pin
  `versionNegotiation: { mode: { pin: "2026-07-28" } }` in tests or you silently test the
  fallback path.
- Browser `EventSource` cannot send an `Authorization` header — the view's live stream is
  fetch-streamed for this reason. Related: `networkidle` never fires on the room page (the
  stream holds a connection open); wait on selectors instead.
- The e2e suite's v1-SDK client is **deliberate** (legacy-era coverage) — don't migrate it.
- Same-millisecond Room creation needs an ordering tiebreak (store contract covers it).
- `docs/superpowers/` specs/plans are historical artifacts with stale numbers — banner'd,
  don't trust their details.
